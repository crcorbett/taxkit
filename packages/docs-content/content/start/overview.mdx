# Overview

Use TaxKit when you need source-backed tax calculations from TypeScript or
over HTTP. Start with the TypeScript SDK when your application can import
TaxKit packages. Use the HTTP API when the caller uses another language or
the calculation should run on a server. Browser applications can use either
HTTP or the browser-safe SDK entrypoints.

## Choose your first path

| You need to                                 | Start with                                        |
| ------------------------------------------- | ------------------------------------------------- |
| Run one calculation from TypeScript         | [Quickstart](./quickstart.mdx)                    |
| Add TaxKit to a server application          | [Plain SDK](../sdk/plain-sdk.mdx)                 |
| Return typed success or failure values      | [Safe SDK](../sdk/safe-sdk.mdx)                   |
| Compose TaxKit inside an Effect application | [Effect SDK](../sdk/effect-sdk.mdx)               |
| Choose where browser calculations run       | [Choose SDK or HTTP API](./choose-sdk-or-api.mdx) |

## How the public surfaces fit

```ts
Public integration surfaces

TypeScript application on a server or in a browser
  -> @taxkit/sdk plain facade
    -> calculator service

Effect application or in-process transport
  -> @taxkit/sdk/effect
    -> calculator service

Caller using HTTP
  -> HTTP API
    -> calculator service
```

The SDK and API use the same calculator-owned schemas and branded values. This
keeps request validation, calculator reports and expected errors aligned across
surfaces.

## Current release status

Use one `@taxkit/sdk` package for all TypeScript entry points. The engine and
rule packages remain private implementation owners; you do not install them
separately. See [Install the SDK](./install-the-sdk.mdx).
