# Development skills

Maintainers can use the optional
[Commonplace development-workflows plugin](https://github.com/crcorbett/commonplace-plugins/tree/main/plugins/development-workflows).
Use the skills relevant to the task, alongside `AGENTS.md`, the architecture,
package READMEs and scripts. Contributors do not need the plugin.

- `development-workflows:strict-effect-ts`: owned code, tests and tooling.
- `development-workflows:alchemy-iac`: infrastructure and deployment work.
- `development-workflows:effect-client-wrapper`: external service adapters.
- `development-workflows:package-structure`: package boundaries.
- `development-workflows:docs-maintainer`: documentation changes.
- `development-workflows:prd-writer`, `prd-review`, `prd-implementer`: product
  requirements and implementation.
- `development-workflows:repo-structure`: repository structure reviews.
- `development-workflows:structure-review`: finding and fixing package seams,
  repeated facts, misplaced files and dependency direction.
- `development-workflows:codebase-design`: designing a module's interface or
  deciding where a seam goes.
- `development-workflows:grill-with-docs`: stress-testing a consequential
  design choice against code and concrete examples before settling it.
- `development-workflows:domain-modeling`: changing the terms in
  [`CONTEXT.md`](../CONTEXT.md) or recording an ADR in [`adr/`](adr/).
- `development-workflows:linear`: Linear tracking, Changesets and release notes.
- `development-workflows:local-release`: merging and releasing from a
  workstation when the maintainer asks for a local release or CI cannot start.
- `development-workflows:ui-review`: reviewing a Website change before it ships.
- `development-workflows:component-design`: designing React component APIs.
- `development-workflows:design-foundations`: hierarchy, spacing, typography
  and colour decisions.
- `development-workflows:forms-and-inputs`: calculator forms, inputs, buttons
  and validation states.
- `development-workflows:touch-and-accessibility`: touch targets, keyboard
  use, focus and assistive technology.

The repository keeps no copies of these skills. Local source and configuration
determine the actual commands and boundaries.
