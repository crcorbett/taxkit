# Deployment architecture

Alchemy owns deployment of Site's Cloudflare and Axiom resources. The GitHub
quality workflow checks out and tests one exact commit, then passes that SHA
to the delivery workflow. Delivery calls native Alchemy once.

## Preview

The [Preview workflow](../../.github/workflows/cloudflare-branch-preview.yml)
checks the live pull request, owner, repository, label and exact head before
fetching Preview credentials. It derives the stage as `pr-<number>`, rebuilds
the accepted checkout, checks generated assets and runs
`bun alchemy deploy --stage "pr-<number>" --yes`.

The [cleanup workflow](../../.github/workflows/cloudflare-branch-preview-cleanup.yml)
uses trusted default-branch code, checks the current pull request again, and
runs `bun alchemy destroy alchemy.destroy.ts --stage "pr-<number>" --yes`.
Shared Production datasets and dashboards are outside that stage.

## Production

The [Production workflow](../../.github/workflows/alchemy-main.yml) requires
`main`, the current GitHub SHA and the same SHA accepted by quality. It uses
the named Production Environment and runs
`bun alchemy deploy --stage prod --yes`.

Production deployment is supported through that workflow. There is no local
Production deploy wrapper. The root `production:plan` command remains an
optional native Alchemy diagnostic.
