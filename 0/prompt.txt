## 4. Calculation flow

**Browser (`calculator.atoms.ts:70-231`).** `calculatorPageAtoms = Atom.family(calculatorId =&gt; ...)`:
- `calculation = calculatorRuntime.fn&lt;CalculatorRunServiceRequest&gt;()(req =&gt; TaxKitRpcClient.calculate(req))` (`:85-90`).
- `submit` (`:114-148`) builds the request with `takeHomeRequestFromForm` / `annualTaxRequestFromForm`. Invalid input sets `formError` and sends `Atom.Interrupt`. Valid input sets `attempt` and the `calculation`.
- `edit` (`:106-113`) and `cancel` (`:101-105`) set `attempt` to none and send `Atom.Interrupt` to `calculation`.
- `view` (`:168-227`, keepAlive) derives `{busy, form, message, report, stale}`, falling back to `savedReport` / `savedMessage`. Errors are mapped through `calculationFailureMessage` (`calculation-failure.ts:9-29`), which shows safe tagged messages and a generic fallback.
- Legacy home aliases are at `:235-251`.

**Containers.** `take-home.container.tsx` and `calculator-page.container.tsx`:
- Seed the server submission with `useAtomInitialValues` (`take-home:44-69`, `calculator-page:47-59`).
- On unmount, interrupt the calculation (`take-home:80-83`, `calculator-page:68-72`) and the browser tools (`:71-74` / `:61-64`).
- The views render `&lt;form action="/" method="post"&gt;` (`take-home.view.tsx:28-34`) or `action={`/calculators/${calculatorId}`}` (`calculator-page.view.tsx:43-49`). With JavaScript, `onSubmit` calls `preventDefault()` and then `onCalculate()`.
- The button shows "Calculating…" and is disabled while busy. Messages render with `role="alert"`. The result views use `aria-live="polite"` and show a stale notice (`take-home-result.view.tsx:20-22`, `calculator-page-result.view.tsx:36-38`).

**No-JavaScript POST (`src/server.ts:124-133, 167-261`).**
1. Only POSTs to `/`, `/calculators/au.income-tax.annual` and `/calculators/au.pay.withholdings` are handled. Other POSTs get a 404 (`markdown.response.server.ts:28-30`).
2. The handler is wrapped in `withCalculatorRequestBodyLimit(..., CalculatorRequestBodyPolicy.make({ responseFormat: "html" }))`.
3. It reads `formData()` and decodes `AnnualTaxForm` or `TakeHomeForm`; failures are `WebsiteInputError` → 400.
4. It calls `application.calculate` under `Effect.result` and encodes a `WebsiteSubmission`.
5. It re-renders as a synthetic GET with `content-length` and `content-type` removed, passing `{ context: { submission } }`. The root loader then forwards `serverContext.submission`.

**Body limit** (`packages/api/http/src/request-boundary.ts`):
- `CalculatorRequestBodyLimit = ByteSize.kibibytes(64)` (`:33`) and `CalculatorRequestBodyDeadline = Duration.seconds(5)` (`:34`).
- The stream is counted chunk by chunk with a timeout, plus a monotonic-clock re-check for late synchronous reads (`:50-83`).
- Failures return 413 (size) or 408 (deadline) as a fixed HTML page (`:84-102`).

**Cancellation:**
- The request signal is passed to `appRuntime.runPromise` (`server.ts:283`) and to the server-function runners.
- Browser: `Atom.Interrupt` on edit, cancel or unmount.
- The binding RPC path cannot carry an abort signal (`live.server.layer.ts:60-62`).
