Thanks for the TaxKit evidence. One related case to check: you said the docs 400/406/404/503 negotiation replies carry `Vary: Accept`. If any of them is `no-store` at the same URL as the docs HTML, it can still evict the cached page.

Site Preview, 13 October, one fresh /about URL:
plain MISS → plain HIT → `Accept: text/markdown;q=bad` gives 406, `cache-control: no-store`, BYPASS → plain MISS.
The no-store reply dropped the cached page despite an identical Vary set. adad saw the same with a no-store 308. That means anyone can empty a page's cache entry with an odd Accept header.

Site's fix: negotiation answers that depend only on Accept (400 and 406) get the page's public cache policy and are stored as their own variant. Errors that mean "unavailable" (503) stay no-store. A 404 at a URL that has no cached page doesn't matter.

Suggested check on a docs URL: warm the HTML, send an unusual Accept that yields 400 or 406, then request the HTML again; it must stay a HIT. If it drops, store those negotiation answers publicly.
