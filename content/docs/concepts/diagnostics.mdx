# Diagnostics

Diagnostics explain calculation health and metadata quality. They are part of
the public calculation model, not private debug output.

## When this matters

Use diagnostics when you need to show validation issues, inspect graph health
or test that a calculator ran without metadata problems.

## How it works

`CalculatorRunResponse` includes a `diagnostics` field beside the calculator
metadata and report:

The program returns an Effect for your application host to run. Inspect
`run.diagnostics.graphIssues` in the resulting checked run.

```ts
import { Effect } from "effect";
import { calculateRun } from "taxkit/effect";
import { AuPayTakeHomeCalculation } from "taxkit/au";
import { TakeHomeScenarioInputSchema } from "taxkit/au/schemas";
import { Cents, Money, NonNegativeMoney } from "taxkit/money";

const scenario = TakeHomeScenarioInputSchema.make({
  grossPay: NonNegativeMoney.make(Money.fromCents(Cents.make(165_400))),
  period: "weekly",
  taxFreeThresholdClaimed: true,
});
const program = calculateRun(AuPayTakeHomeCalculation, scenario);
```

The current take-home pay success fixture has no graph issues.

## Trace and graph data

Trace data records which rule ran, what it used, what it produced and which
sources support it. Graph data exposes dependency edges and validation issues
through the calculator graph endpoint.
